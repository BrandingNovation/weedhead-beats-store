# Data Storage Guide - Where Everything is Saved

## 📍 Current Data Storage Locations

### ✅ **Saved to Supabase (Persisted in Database)**

#### 1. **Blog Posts** (`posts` table)
- **Location**: Supabase PostgreSQL database
- **Table**: `posts`
- **Fields**: `id`, `title`, `excerpt`, `image`, `content`, `is_ai_generated`, `created_at`
- **Status**: ✅ **Persisted** - Saved permanently in Supabase
- **Image Storage**: 
  - AI-generated images: Saved as **base64 data URLs** in the `image` field (text)
  - Manual uploads: Can be uploaded to Supabase Storage `covers` bucket, or use external URLs
  - **⚠️ Issue**: Base64 images in database are inefficient (very large, slow queries)

#### 2. **Tracks/Beats** (`tracks` table)
- **Location**: Supabase PostgreSQL database
- **Table**: `tracks`
- **Status**: ✅ **Persisted** - Saved permanently in Supabase
- **Cover Images**: Supabase Storage → `covers` bucket (public)
- **Audio Files**: Supabase Storage → `audio` bucket (public)

#### 3. **Orders** (`orders` table)
- **Location**: Supabase PostgreSQL database
- **Status**: ✅ **Persisted**

#### 4. **Cart Items** (`cart_items` table)
- **Location**: Supabase PostgreSQL database
- **Status**: ✅ **Persisted**

#### 5. **User Profiles** (`profiles` table)
- **Location**: Supabase PostgreSQL database
- **Status**: ✅ **Persisted**

---

### ❌ **NOT Saved to Supabase (Only LocalStorage)**

#### 6. **CMS Content** (Hero Images, Page Content)
- **Location**: Browser `localStorage` only
- **Key**: `weedhead_cms_content`
- **Status**: ❌ **NOT Persisted** - Lost if:
  - User clears browser cache
  - User uses different browser/device
  - Browser storage is full
  - User is in incognito mode
- **⚠️ CRITICAL ISSUE**: CMS content is NOT saved to Supabase!

**What's in CMS Content:**
- Store page hero image
- Collabs page content
- Licenses page content
- Blog page content

---

## 🔍 Detailed Breakdown

### Blog Images Storage

**Current Implementation:**
1. **AI-Generated Images**:
   - Generated by Gemini API as base64 data
   - Format: `data:image/png;base64,iVBORw0KGgoAAAANSUh...` (can be 100KB+)
   - Saved directly in `posts.image` field as text
   - **Problem**: Very large database rows, slow queries

2. **Manual Uploads**:
   - Can upload to Supabase Storage `covers` bucket
   - Gets public URL: `https://your-project.supabase.co/storage/v1/object/public/covers/filename.jpg`
   - Saved as URL in `posts.image` field
   - **Better**: More efficient, faster

**Recommended Fix:**
- Upload AI-generated images to Supabase Storage instead of saving base64
- Convert base64 → File → Upload to Storage → Save URL

---

### CMS Content Storage

**Current Implementation:**
- Stored in `localStorage.getItem('weedhead_cms_content')`
- Only exists in the user's browser
- Not synced across devices
- Not backed up

**Recommended Fix:**
- Create a `site_content` table in Supabase
- Store CMS content in database
- Sync across all devices
- Admin-only access

---

## 🗄️ Supabase Storage Buckets

### Required Buckets:

1. **`covers`** (Public)
   - Track cover images
   - Blog post images (manual uploads)
   - File size limit: 50MB
   - MIME types: `image/jpeg`, `image/png`, `image/webp`

2. **`audio`** (Public)
   - Audio files (beats, samples)
   - File size limit: 100MB
   - MIME types: `audio/mpeg`, `audio/wav`, `audio/mp3`, `audio/m4a`

### How to Create Buckets:

1. Go to **Supabase Dashboard → Storage**
2. Click **"New Bucket"**
3. Create:
   - Name: `covers`, Public: ✅
   - Name: `audio`, Public: ✅
4. Set file size limits and allowed MIME types

## 🔧 Recommended Improvements

### 1. Move CMS Content to Supabase

Create a `site_content` table:
```sql
CREATE TABLE site_content (
    id UUID PRIMARY KEY DEFAULT uuid_generate_v4(),
    page TEXT NOT NULL, -- 'store', 'collabs', 'licenses', 'blog'
    hero_image TEXT,
    content JSONB,
    updated_at TIMESTAMPTZ DEFAULT NOW(),
    updated_by UUID REFERENCES auth.users(id)
);
```

### 2. Upload AI-Generated Images to Storage

Instead of saving base64 in database:
1. Convert base64 → Blob → File
2. Upload to Supabase Storage `covers` bucket
3. Get public URL
4. Save URL in database

This will:
- Reduce database size
- Speed up queries
- Make images load faster
- Allow CDN caching
